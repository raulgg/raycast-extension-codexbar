# A Provider removed from the upstream CodexBar codebase is deleted here as a directory

The Provider is removed in the upstream CodexBar codebase: the pinned revision no longer includes its descriptor. `npm run upstream:prune` then deletes this extension's `src/providers/<id>/`, regenerates `src/providers/index.ts`, and drops that id from the catalog order and from the allowlists `upstream:check` reads. An icon file is deleted only when no remaining Provider uses its slug. A quoted id, module path, or URL segment that would survive that edit blocks the write, so the catalog row is still there on the next run.

`npm run upstream:bump` writes `codexbar-upstream.lock` only after `npm run typecheck` and `npm test`, including when the prune plan is empty. `upstream:check` does not typecheck. A failed typecheck or test after prune changed files restores that snapshot and does not write the lock. A failure when the plan is empty only withholds the lock. If `upstream:check` fails after a prune that changed files, those edits stay and the lock is not written. The statement rewriter that used to edit call sites is gone: a leftover reference is a person's edit.
